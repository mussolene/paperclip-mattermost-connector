# Сопоставление с Slack

## Область сравнения

Сравнение относится к реализации Slack в Paperclip `v2026.1023.0`, коммит `1b4c803816e82b0265c8422e1a804327a7ed8c54`, и к этому плагину Mattermost. Официальная реализация Slack является частью серверного кода Paperclip. Плагин Mattermost является отдельным расширением SDK. Это разные уровни интеграции.

Обозначения:

- **Официальный Slack**: встроенная интеграция Paperclip, описанная в документации и исходном коде указанного тега.
- **Режим Socket Mode сообщества**: внешний прием событий Slack через соединение Socket Mode. Такой транспорт сам по себе не означает поддержку официального набора функций Paperclip.
- **Этот плагин**: исходный Mattermost-плагин из локальной ревизии `ebaf0a4`, извлеченный и адаптируемый для независимой установки.

Наличие событий или ответов в ветке не означает полного соответствия встроенной интеграции Slack. Плагин не заявляет паритет с официальной интеграцией.

## Функции и ограничения

| Возможность | Официальный Slack | Этот плагин Mattermost |
|---|---|---|
| Прием сообщений | События Slack проходят проверку подписи и контекста рабочего пространства, соединения, задачи, запуска и связанного пользователя. | Mattermost WebSocket и минутная сверка получают сообщения из разрешенных каналов. Пользователь проверяется по статическому `allowedUserIds`. |
| Идентичность пользователя | Используется активная связанная учетная запись Slack. Доступ повторно проверяется; отключение связи или отзыв доступа ограничивает сохраненные запуски. | Нет связи пользовательских учетных записей Mattermost с Paperclip. Списки разрешенных ID задаются в конфигурации. Нет проверки актуального членства для каждого действия. |
| Личные сообщения | `slack_open_dm` открывает или возобновляет только личный чат бота с текущим связанным ответственным пользователем. Чужие личные сообщения недоступны. | Отдельного разрешения личных чатов и операции открытия личного чата нет. Вход ограничен указанными каналами. |
| Консультации и продолжение | Slack связан с задачами, запусками и ответственным пользователем. Сообщения человека на Slack-связанной задаче передаются в исходную ветку с атрибуцией автора; доставка ведется через устойчивую очередь. | Консультационная сессия связывается с агентом и веткой Mattermost. Ответ отправляется в исходную ветку. Созданные задачи получают итоговые комментарии агента, после чего результат возвращается в ветку. Полный обмен ответами между задачей Paperclip и веткой Mattermost не реализован. |
| Остановка сессии | Встроенный сервер разбирает проверенное событие `agent_session_stopped` и обновляет состояние Slack-сессии. | Нет приема события остановки Slack-подобного типа и синхронизации статусов с внешним чатом. SDK предоставляет управление сессиями Paperclip, но это не является адаптером внешнего чата. |
| Инструменты Slack | Есть строгий каталог методов, областей доступа и схем аргументов. Каждое обращение повторно проверяет доступ. | Плагин использует API Paperclip и собственные операции Mattermost. Нет каталога инструментов Slack и соответствующего шлюза проверки прав. |
| Подтверждение действий | Потенциально опасные операции, например удаление сообщения или приглашение участника, требуют подтверждения. Есть устойчивые квитанции операций и повторная проверка перед отправкой. | Нет эквивалентной очереди внешних действий с квитанциями и подтверждением в шлюзе Paperclip. Возможности SDK для регистрации инструментов не создают такую интеграцию автоматически. |
| Источники и публикация | Встроенная интеграция хранит происхождение приватного содержимого и ограничивает последующую публикацию. | Нет учета происхождения приватного содержимого и связанных ограничений публикации. |
| Повторная доставка | Есть устойчивые ключи идемпотентности, квитанции отправки и сверка неопределенного результата. | Есть локальная дедупликация ответов и задач и периодическая сверка. Гарантии не эквивалентны серверной очереди Slack и ее квитанциям. |

У этого плагина есть полезные функции для Mattermost: отдельный профиль для агента, WebSocket-прием, список разрешенных каналов и пользователей, консультационные сессии, создание задач по поручению, возврат результата в ветку, повторная сверка и, при настройке, автоматическое создание профилей ботов. Они не покрывают перечисленные выше механизмы идентичности, полномочий и управляемых действий Slack.

Режим Socket Mode сообщества относится к способу транспортировки событий Slack. Он не предоставляет сам по себе встроенную модель Paperclip для связанных личностей, происхождения приватных данных, подтверждения действий, продолжения задачи, квитанций доставки и синхронизации остановки. Этот документ не оценивает отдельную реализацию Socket Mode и не утверждает ее свойства.

## Возможности SDK и граница расширения

Документация SDK версии из указанного тега описывает регистрацию плагина, события и задания, инструменты плагина, а также сессии агентов `create`, `list`, `sendMessage` и `close`. Эти API позволяют строить внешние рабочие процессы и чат-сессии внутри Paperclip. В просмотренной поверхности SDK нет публичного интерфейса регистрации полноценного провайдера внешнего чата с admission, связью личности, маршрутизацией сообщений, статусом сессии и политикой публикации.

Следующие расширения SDK могли бы предоставить общую основу для сторонних чатов:

1. Контракт регистрации внешнего чат-провайдера с обработчиками проверенного входящего события и исходящей доставки.
2. Модель связи пользователя внешнего сервиса с ответственным пользователем Paperclip и повторной проверки членства и отзыва доступа.
3. Привязка внешнего разговора к задаче и запуску, включая атрибуцию человеческих сообщений и маршрутизацию ответов.
4. API статуса и остановки внешней сессии с устойчивой дедупликацией событий.
5. Общий шлюз инструментов провайдера для проверок полномочий, запросов подтверждения, квитанций операций, идемпотентности и безопасного повтора.
6. Учет происхождения приватных данных и правил публикации между исходными каналами.

Пока такой контракт не опубликован и не реализован, плагин остается отдельным Mattermost-коннектором. Добавление этих механизмов только внутри плагина потребовало бы собственной модели личности, очередей и разрешений; это не сделало бы ее частью штатного шлюза Paperclip.
