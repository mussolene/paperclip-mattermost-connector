# Архитектура Mattermost-плагина

## Назначение

Плагин соединяет разрешенные каналы Mattermost с выбранными агентами и задачами Paperclip. Он устанавливается как обычный плагин SDK и исполняется в отдельном процессе плагина. Это внешний коннектор, а не встроенный провайдер чата Paperclip.

Исходная ревизия извлеченного Mattermost-плагина: `ebaf0a4`. Текущая архитектура описывает самостоятельное расширение, основанное на этой исходной версии. В проект не переносилась реализация Slack из Paperclip.

## Части системы

| Часть | Ответственность |
|---|---|
| `manifest.js` | Идентификатор и версия плагина, возможности SDK, схема настройки и расписание сверки. |
| `src/worker.js` и `src/runtime.js` | Создание runtime плагина, запуск SDK worker и подключение обработчиков. |
| `src/socket.js` | Управление отдельными Mattermost WebSocket-соединениями для настроенных профилей ботов. |
| `src/mattermost.js` | HTTP-вызовы Mattermost и транспортные операции. |
| `src/service.js` | Проверка входящих сообщений, выбор агента, консультационные сессии, доставка ответов, создание задач и восстановление незавершенных операций. |
| `src/core.js` | Общее связывание Paperclip и Mattermost, включая маршрутизацию, фильтры и обработку событий. |
| `src/config.js` и `src/provisioning.js` | Проверка настроек и, если включено, создание профилей Mattermost для агентов. |
| `src/worker.js` | Пусковая точка регистрации и исполнения плагина через SDK. |

## Поток сообщения

1. Сообщение приходит через WebSocket или минутную сверку.
2. Плагин проверяет идентификатор канала и автора по настроенным спискам, отбрасывает собственные и системные сообщения.
3. Плагин определяет адресованного бота и режим сообщения. Консультация использует сессию агента; явное поручение создает задачу Paperclip.
4. Ответ консультации либо итоговый комментарий по задаче отправляется в исходную ветку Mattermost.
5. Состояние плагина используется для устранения повторов и сверки после перезапуска.

Код плагина вызывает доступные сервисы Paperclip SDK. Для задач он использует обычные задачи Paperclip, а для консультации API сессий агента. Внешняя идентичность пользователя остается Mattermost ID в конфигурации плагина и событиях Mattermost.

## Возможности Paperclip SDK

Плагин объявляет и использует возможности, нужные для выбранного потока: чтение агентов, создание и чтение сессий, отправка сообщений в сессии, чтение и создание задач, запрос пробуждения задачи, чтение комментариев, подписка на события, состояние плагина, плановые задания, исходящие HTTP-запросы и разрешение ссылок на секреты.

Секреты Mattermost передаются как ссылки `secret_ref`. В документации настройка автоматического создания профилей также включает секрет учетной записи администратора и ключ шифрования сохраненных токенов. Токены профилей, созданных автоматически, хранятся в зашифрованном виде в состоянии Paperclip.

Регистрация инструментов плагина через SDK и API сессий агента не равны регистрации провайдера чата. Проверенные в upstream-документации SDK поверхности позволяют исполнять расширения плагина, но не задают общий шлюз идентичности, продолжения внешнего разговора, согласования действий и публикации из приватных источников.

## Границы безопасности и поведения

- Пользовательский доступ управляется статическим `allowedUserIds`, а доступ по каналам статическим `channelIds`.
- Плагин не выполняет отдельную привязку личности Mattermost к учетной записи Paperclip.
- Плагин не получает штатную серверную проверку членства и отзыва связи пользователя, аналогичную встроенному Slack.
- Для личных сообщений нет операции разрешенного открытия личного чата текущего связанного ответственного пользователя.
- Нет общего шлюза внешних операций с подтверждениями, квитанциями доставки и повторной проверкой полномочий перед отправкой.
- Нет модели происхождения приватного содержимого, ограничивающей последующую публикацию.
- Нет штатной связи ответа в Paperclip с исходным внешним чатом для всех человеческих сообщений задачи.
- Управление сессией Paperclip не синхронизирует автоматически внешние статусы или сигнал остановки Mattermost.

Эти ограничения обозначают отличие архитектуры, а не обещание будущей поддержки. Не следует трактовать существующую дедупликацию и периодическую сверку как гарантию эквивалентных серверных квитанций или как политику подтверждения действий.

## Путь к расширению SDK

Чтобы предоставить полноценное расширение внешнего чата для разных плагинов, SDK и Paperclip могли бы определить общий провайдерский контракт для проверенного входящего события, связанных пользователей и полномочий, привязки чата к задаче, остановки и статуса сессии, исходящей доставки и шлюза управляемых действий. Такой контракт должен включать повторную проверку актуального доступа и устойчивые квитанции. До его появления интеграции на уровне плагина следует описывать как самостоятельные коннекторы с собственными ограничениями.
